# 第 3 周笔记：岗位筛选 + 网页版

## 一句话本质
**把"一次一个 JD 的深度流程"变成"一次十个 JD 的快速流程"，再把两条流程搬上网页**：并行（Send）解决快，SSE 解决等待体验，脱敏 + 不落盘解决"敢不敢把简历交给别人的网站"。

## 流程图

```
岗位筛选：START ─Send×N→ [解析 JD → 匹配打分(快模型) → 风险检查 → 建议] ─→ 汇总排序 → END
                            （每个 JD 一个并行分支，最多同时 4 个）

网页：浏览器（简历存本地）─POST + SSE─→ FastAPI ─后台线程→ LangGraph 图
                                     ←── 进度事件 / 人工确认 / 报告 ──
```

## 新概念

| 概念 | 是什么 | 本项目里怎么用 |
|---|---|---|
| Send | 条件边返回 `[Send("节点", 子输入), ...]`，有几个就开几个并行分支；每个分支只拿到自己的子输入 | 每个 JD 一个分支，结果用 `operator.add` 合并进 `results` |
| map-reduce | 先"分发"（map）并行处理，再"汇总"（reduce） | `fan_out` → `screen_one` × N → `rank` |
| max_concurrency | config 里限制同时跑几个分支 | 设 4，防止 10 个 JD 同时打模型被限流 |
| get_stream_writer | 节点里发自定义事件，调用方用 `stream_mode="custom"` 收到 | "第 3 个 JD 正在查风险" |
| SSE | 服务器推送事件：一个不关闭的 HTTP 响应，每有进度就写一段 `event:` + `data:` | 筛选、深度准备的进度实时推给浏览器 |
| ContextVar | 每个请求独立的"全局变量"，并行任务会复制它 | 用户自带的 DeepSeek Key 只在本次请求有效，不写环境变量 |
| Depends | FastAPI 的依赖：在接口函数执行之前先跑 | 参数检查、限额放这里（流式接口一旦开始输出就改不了状态码） |
| Langfuse 回调 | 把回调放进 config，LangChain 自动传给图里每次模型调用 | 配了 Key 就记录完整执行轨迹，没配就不启用 |

## 评测结果

| 评测 | 结果 |
|---|---|
| 并行效果（17 个 JD，并发 4） | 总耗时约 55 秒，逐个跑约 200 秒 |
| 风险类型（有标注的 7 个 JD） | 召回 100%；精确率 90%～100%（多次运行有波动，多报的是"5-10 年 vs 五年以上"算不算矛盾） |
| 快模型做差距分析 vs 强模型 | 8 个 JD 中 7 个分数差 ≤ 7 个百分点，校验问题 0 条，耗时约一半 → 筛选用快模型 |
| 截图识别 | 2 个 JD 各 3 张截图，人工文本中 96% 的内容被识别出 |
| 网页端到端（真实模型） | 筛选 3 个 JD → 点"深度准备" → 停在人工确认（2 条：一条夸大、一条编造年限，都拦对了）→ 拒绝 1 条、手改 1 条 → 报告正确反映两种处理 |
| 隐私 | 服务器存档里真名出现 0 次（占位符 39 次）；报告返回浏览器时已还原 |
| 测试 | 34 个全部通过（31 离线 + 3 真实调用） |

## 实测发现的问题和处理

| 发现 | 处理 / 教训 |
|---|---|
| 大公司几乎都查得到劳动仲裁，"公司负面"一律降档，药明康德 100% 匹配被降成"改简历后投" | 公司负面只展示不降档；只算近两年的裁员、欠薪。**规则的阈值要用真实数据校准** |
| 华宝证券因为 2012 年的旧闻被降成"放弃" | 同上；深度准备的调研缓存也要过同一道筛选，不能直接拿来用 |
| "猎头代招"被推断成外包驻场 | 提示词明确：没写公司名不算外包，必须有原文依据 |
| 同一类风险换个说法报两次 | 同类只留一条 |
| 同一条简历原文给了两种改写 | 每条原文只留第一个 |
| 流式接口里抛 HTTPException，前端只看到连接断开 | 检查挪到 `Depends`。**流一旦开始，响应头就发出去了** |
| 网页上人工修改的改写里写了真名，存档会出现真名 | `Masker` 记住从简历识别出的名字，修改文本先脱敏再存 |
| 截图识别结果里有招聘者姓名 | 提示词要求忽略招聘者个人信息 |
| 切换标签页后筛选结果丢失 | 标签页只隐藏不卸载 |
| 本机 8000 端口被 Docker（Dify）占用 | 后端统一用 8001 |
| Langfuse 服务器连不上时会不会拖垮业务 | 实测：轨迹在后台异步上报，失败只打日志，业务照常 |

## 已知局限

| 局限 | 想法 |
|---|---|
| 截图识别会认错字（"字蒙"→"宇蒙"），公司名错了调研会搜错 | 识别结果放在可编辑文本框里让用户核对；以后可以把公司名单独高亮提示 |
| 免费额度记在内存里，重启清零；按 IP 限流可被绕过 | 第一版够用；上线后看滥用情况再加设备指纹或简单登录 |
| 网页存档（`web_checkpoints.sqlite`）只增不删 | 第 4 周部署时加定期清理（如 7 天前的任务） |
| 用户 Key 会留在模型实例缓存里（最多 64 个） | 只在进程内存中，不落盘；以后可改成不缓存 |
| Langfuse 只验证了"连不上不影响业务"，没看到真实轨迹 | 需要 Key（见下） |
| 风险类型只有 7 个 JD 的标注 | 继续积累 |

## 常用命令（在 job-agent 目录下）

| 做什么 | 命令 |
|---|---|
| 启动网页 | `uv run uvicorn job_agent.api:app --port 8001`，浏览器开 http://localhost:8001 |
| 改了前端后重新打包 | `cd web; npm run build` |
| 前端开发（热更新） | `cd web; npm run dev`，开 http://localhost:5173 |
| 筛选评测 | `uv run python evals/run_screen_eval.py` |
| 离线测试 | `uv run pytest -q -k "not live"` |
