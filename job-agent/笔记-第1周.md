# 第 1 周笔记：骨架、模型适配、结构化解析、脱敏

## 一句话本质
**把"不确定的模型输出"关进确定的边界里**：pydantic 规定输出格式，行号让输出可核对，脱敏让输入可放心。

## 文件地图

| 文件 | 作用 |
|---|---|
| `src/job_agent/core/llm.py` | 模型适配：`structured(Schema, "fast" / "strong")`，用环境变量切换厂商 |
| `src/job_agent/core/pii.py` | 脱敏：正则替换手机号、邮箱、身份证号、姓名，之后可还原 |
| `src/job_agent/job/schemas.py` | `JobPosting`、`Resume` 数据结构 |
| `src/job_agent/job/parse.py` | `parse_jd`、`parse_resume`、`check_citations` |
| `evals/run_parse_eval.py` | 解析评测，输出指标表 |
| `tests/` | 离线测试 4 个 + 真实调用测试 3 个（没有 Key 自动跳过） |

## 实测得出的设计决策

| 决策 | 依据（实测） |
|---|---|
| 结构化输出统一用 `function_calling` | DeepSeek 的 `json_mode` 不会把字段定义发给模型，模型自己编了 `employment_type`、`client` 等字段，校验失败 |
| DeepSeek 统一关闭思考模式 | 思考模式下强制调用工具直接返回 400；而 LangChain 官方文档还停留在旧模型名 `deepseek-chat`，说明**框架文档会落后于厂商，以实测为准** |
| 简历先编行号，模型抽取时标注 `lines` | 程序可以核对每一条是否真的出自原文；在真实简历上，36～42 条全部核对通过 |
| 脱敏用正则，不靠模型 | 模型可能漏掉，而且数据一旦发出去就收不回来；确定性规则可测试 |
| `Field(description=...)` 写抽取规则 | description 会随 schema 一起发给模型，等于写在字段上的提示词 |

## 三模型对比（3 个 JD：1 个合成 + 2 个真实；1 份真实简历）

| 指标 | deepseek-flash | qwen-plus | claude-haiku-5.5（OpenRouter） |
|---|---|---|---|
| 硬性要求召回（平均） | **97%** | 78% | **97%** |
| 关键词 准确 / 召回（平均） | 83% / 94% | **97%** / 71% | 85% / 94% |
| 用工线索准确率（3 个 JD） | **3/3 全对** | 2/3 | 1/3 |
| 简历引用问题数 | 0 / 42 条 | 1 / 36 条 | 0 / 36 条 |
| 平均耗时 / JD | **2.3s** | 11.5s | 4.0s |
| tokens / 3 个 JD | 5.4k | 4.7k | 8.8k |

**结论**：解析这一步 deepseek-flash 又快、又准、又便宜，可以作为"快模型"的默认值。Qwen 偏保守（抽得少但准），Claude 容易把不属于用工线索的内容也抽进来。**样本只有 3 个 JD，结论要等评测集补到 15 个以上再确认。**

## 这一轮实测发现的问题

| 发现 | 教训 / 处理 |
|---|---|
| Claude 抽出了原文没有的"经常出差"，正好是我写在字段说明里的示例词 | **提示词里的示例会泄漏到输出中**。处理：用工线索必须是原文片段，由程序过滤（和简历行号核对是同一种思路） |
| 模型把"招 2 人""修线上问题"当成用工线索 | 原文核对拦不住"原文里有、但归错类"的情况，只能靠字段说明写清边界 + 评测准确率来发现 |
| 评测只算召回率时，看不出上面这个问题 | **只看召回率会被"多抽"骗过**，必须同时看准确率 |
| 匹配函数最初只检查了单向包含，把正确答案判成了错 | 评测代码本身也会有 bug。指标异常时先看原始输出，不要直接相信数字 |
| 字蒙的 JD 标题写 3～5 年，正文写 1～2 年，三个模型各取各的 | JD 内部的自相矛盾值得提醒用户，留到第 3 周的风险标签 |
| 大润发的"年龄 33 以下" | 年龄限制同样应该进入风险标签 |
| 同一份简历，同一模型两次解析分别得到 42 条和 36 条 | **temperature=0 也不完全稳定**，正式评测要多跑几次取平均 |

## Key 管理
Key 放在项目根目录的 `.env`（从 `E:\AI\LangChain\.env` 复制而来，已加入 .gitignore），由 `llm.py` 在导入时用 python-dotenv 加载。
已经存在的环境变量优先，所以临时换 Key 只需在终端里设置 `$env:XXX`。
为什么不用系统环境变量：程序只在**启动时**继承环境变量，VS Code 没有完全退出时，新开的终端还是拿到旧环境；`.env` 跟着项目走，不受这个影响。
