# 第 0 步笔记：手写最小 ReAct 循环

## 一句话本质
**Agent = while 循环 + messages 列表 + 工具表。** 模型负责"决定下一步做什么"，程序负责"真的去做，再把结果告诉模型"。

## 概念速查

| 概念 | 是什么 | 在代码里对应 |
|---|---|---|
| ReAct | Reason（想）→ Act（调工具）→ Observe（看结果），循环直到能回答 | `react()` 里的 `for step` 循环 |
| Function Calling | 模型不直接执行工具，而是输出"我要调用 X，参数是 Y"（结构化 JSON） | `msg.tool_calls` |
| 工具 Schema | 给模型看的"工具说明书"（JSON Schema）。模型只看得到说明书，看不到函数代码 | `TOOL_SCHEMAS` |
| 状态 / 短期记忆 | 整个对话历史，每一轮都把全部历史重新发给模型（模型本身不记事） | `messages` 列表 |
| tool 消息 | 把工具结果送回模型，用 `tool_call_id` 对应是哪一次调用 | `{"role": "tool", ...}` |
| 终止条件 | 模型不再请求工具，就说明它认为可以回答了 | `if not msg.tool_calls: return` |

## 4 个设计决策（面试要能讲清楚）

| 决策 | 为什么 |
|---|---|
| 步数上限 `MAX_STEPS` | 模型可能反复调用工具，不设上限会死循环、白花钱 |
| 工具出错返回文字，不抛异常 | 模型看到"出错了"可以换参数重试，这就是 Agent 的自我纠错 |
| `read_file` 限制在 data 目录、计算器不用 `eval` | 工具参数由模型生成，**不可信**，要当成用户输入来校验（最小权限、防注入） |
| 用原生 Function Calling，不用论文里的文本解析 | 原论文让模型输出 `Action: xxx` 文本，再用正则解析，容易出格式错误；现在的模型原生支持结构化调用，LangChain 底层也是这样做的 |

## 对后面学框架的意义：LangGraph 帮你省了什么

| 手写版的局限 | 框架里的对应能力 |
|---|---|
| `messages` 只在内存里，程序一退出就没了 | checkpointer：持久化状态，可以断点续跑 |
| 中途没法暂停等人确认 | `interrupt`：人工介入 |
| 只有一条直线循环 | 图结构：分支、并行（`Send`）、子图 |
| 换模型要改代码 | LangChain `init_chat_model`：改配置就能换 |
| 只能 print 看轨迹 | LangSmith / Langfuse 追踪 |
